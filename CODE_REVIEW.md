# Ревью кода

Дата: 28 октября 2026 года.

Проверены интерфейс, воспроизведение, экзамен, сохранение и удаление истории,
сборка Windows и состав файлов для репозитория. Существующие 27 тестов проходят.
Ниже перечислены открытые замечания; прохождение тестов не означает их отсутствия.

## P1 — Потеря попыток при одновременном запуске двух экземпляров

`learning.py`, методы `record`, `_commit`, `delete_attempts` и `clear_history`.

Каждый экземпляр загружает историю один раз и затем сохраняет полную копию из
памяти. Если запустить два окна и завершать задания попеременно, последнее
сохранение перезаписывает результаты другого окна. Фиксированное имя
`progress.tmp` также создаёт конфликт при одновременной записи.

Воспроизведение: первый объект сохраняет `first`, второй загружает историю;
первый сохраняет `second`, второй — `third`. На диске остаются `first, third`.
`second` теряется. Этот сценарий воспроизведён на отдельном тестовом файле.

Рекомендуемое исправление: блокировка общей операции чтения–изменения–записи
между процессами с перечитыванием актуального файла либо запрет одновременного
запуска приложения. Одна атомарная замена файла не предотвращает потерю обновлений.

## P2 — Неполная проверка структуры истории приводит к исключению при удалении

`learning.py`, загрузка `history` и метод `delete_attempts`.

Загрузчик проверяет только то, что элементы истории являются словарями, но
удаление использует обязательные `original` и `typed`. JSON с записью
`{"id":"bad","eligible":true,"status":"completed"}` принимается как корректный;
удаление вызывает `KeyError: original`. Обработчик интерфейса перехватывает лишь
`OSError`, поэтому сообщение об ошибке пользователю не показывается.

Сценарий воспроизведён на отдельном тестовом файле. Нужно проверять поля, типы,
допустимую длину текстов, уникальность идентификаторов и согласованность статуса
при загрузке, сохраняя повреждённый файл для восстановления.

## P2 — Экзамен закрывается после неудачного сохранения

`adkm85.py`, методы `save_attempt` и `check`.

`save_attempt` показывает предупреждение при `OSError`, но не возвращает признак
успеха. `check` после этого переводит экзамен в `submitted` и блокирует повторную
сдачу. Если запись была временно недоступна, результат нельзя сохранить повторно
через интерфейс; при закрытии окна он будет потерян.

Вывод основан на потоке управления в исходниках. Нужно отделить завершение
экзамена от сохранения и предоставить повторное сохранение готового результата
без нового прослушивания и без дублей.
